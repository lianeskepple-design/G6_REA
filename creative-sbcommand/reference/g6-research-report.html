1. 背景与目标

Sound BlasterX G6 是 Creative 的 USB 声卡，Sound Blaster Command 通过 USB 下发参数， Windows 侧由 KSUSBAPO64.dll（64 位 APO）和 KSUSBSPI64.dll（属性/控制接口）参与处理。 项目目标不是简单调 EQ，而是回答三个问题：

  1. G6 的每个音效在主机侧到底有没有实现？
  2. 如果有，算法、系数、数据流能不能逐位复刻？
  3. 如果没有，是硬件 DSP、固件，还是只能做参考近似？

约束：本机没有实体 G6（PnP 中 VID_041E&PID_3256 均为 Present=False）， 也没有可用的 USB/IP 直通层；用户已明确 G6 固件提取不现实。因此所有结论只能来自静态逆向、 参数枚举、独立参考对拍和已有抓包，不能声称“实机听感一致”。

4. Surround 专题：逆向矩阵，不是 HRTF

这是最容易被误解的一块。当前 g6_surround.c 实现的是 CMSS3D 五通道增益矩阵， 不是算法工程师 PDF 里的 HRTF 双耳渲染。

4.1 已逆向的部分

  • 0x180093990：mask + strength → 5 个目标增益（前 / 额外 / 中置 / LFE）。
  • 0x180093B30：稳态矩阵，做前/额外增益、中置→前、LFE→额外及后置复制。
  • 0x180093DD0：块内线性过渡斜坡。
  • 常量 0.9535 / 0.3015 是 17.5° 的 cos/sin；0.2875、中置/LFE 的 0.2 / 0.5 / 0.1 都来自反编译。
  • 13 个 mask 分支：0x03b/0x033/0x603/0x60b、0x007/0x00f、0x037/0x03f/0x607/0x60f、0x637/0x63b/0x63f/0x633/0x70f。

4.2 对拍证据

PASS: CMSS3D mask table, steady matrix and transition ramp match

tools/apo-eq-coeff/surround_test.c（C 实现）与独立 surround_ref.py（Python/NumPy） 对 13 个 mask 表、稳态矩阵、8 样本过渡斜坡逐位一致；verify_surround.cmd 现场重跑通过。

5. Bass 与 Dialog+：边界与修正

5.1 Bass：主机 APO 是 bass management，不是 Missing Fundamental

逆向过程中有过两次修正，最终数据流如下：

6 声道输入→ 一阶高通（卫星声道去低频）→ 原始声道 -15 dB 汇总到 LFE/sub→ 软拐点限幅 + 增益包络平滑
  • FUN_180089780：每声道一阶高通，H(z)=c(z⁻¹-1)/(1+a2z⁻¹)，c=-2/(k+2)、a2=(k-2)/(k+2)、k=3π*cutoff/fs。
  • FUN_1800cc170：线性幅度 → dBFS，frexp + 三次 log2 多项式，-6.0206 = -20log10(2)。
  • FUN_1800cc310：dB 域软拐点限幅器。
  • FUN_1800cc560：10-tap FIR 平滑增益包络，不是音频。
  • FUN_1800cb5e0：dB 包络 → 线性增益的三次映射，不是波形整形。

另有一条 CBassMgmtEfxMod（THX bass management）：解析 bass 配置文件的 crossover/boostlevel/virtuallevel，做双二阶交叉滤波 + 128 帧参数淡化。 两条都是 bass management；SBX Bass 的 Missing Fundamental 谐波内核不在主机 APO。

5.2 Dialog+：主机侧只有参数处理器

  • KSUSBAPO64.dll 没有 Dialog 类；32/64 位 APO 的 EfxMod 类名列表一致（各 118 个），均无 Dialog。
  • KSUSBSPI64.dll 只有 THXDialogueAdvantage_Amount/isEnabled 参数处理器： FUN_0044C1AC、FUN_0044C62C，属性 ID 0x100000005/6、0x200000005/6； 处理器 vtable 在 0x4078F0 附近，只做属性读写，没有采样循环。
  • CVocalSuppressorEfxMod（vftable 0x18018de98）是 4 段可交叉淡化滤波器组， 属性 GUID {1ee40950-a46c-45eb-a50c-f1fd995c0166}，更像人声抑制/卡拉 OK，不是 2–4 kHz 对白增强。
  • 结论：Dialog+ 的实际 DSP 未找到，可能在 G6 固件/硬件；当前 g6_dialog.c 是参考近似。

8. 边界与未完成

  • 没有实体 G6：Scout 实机十段、USB id↔频段实测、硬件回环全部暂停。
  • G6 固件提取不现实：用户已明确；因此 SBX Bass 谐波内核、Dialog+ 实际 DSP、HRTF 数据集无法取得。
  • Bass / Dialog+ 是参考近似：按 PDF 的算法类别实现，不是 G6 硬件/APO 的逐位还原。
  • Surround 是矩阵层：公式已逆向/对拍；mask 语义有推断；无 HRTF FIR、ITD/IID、耳机路由。
  • SVM 是全带单检测器压缩器：已按 CPlugAGCCompressor 逐行移植；APO 内没有多频段 AGC/DRC/limiter，也没有模式曲线。
  • Crystalizer 无 +0xF18 输出级：位移扫描 0 次命中，旧结论已撤回。
  • 实时客户端只做立体声：Surround 未放进 sbc-live。
  • Scout 只有互斥语义：模式层关闭 SBX/EQ，Scout 的 DSP 在设备侧，主机未实现。

9. 结论

这个项目已经把“主机 APO 能证明的部分”和“必须靠硬件/固件的部分”分开了：

  • 已证明并复刻：EQ、Crystalizer、CMSS3D 矩阵、Smart Volume，以及它们的数据流/常量/时间常数。
  • 已定位但非谐波内核：Bass 的 bass management 与限幅包络、Dialog+ 的 SPI 参数处理器。
  • 只能参考近似：Missing Fundamental Bass、2–4 kHz Dialog+、HRTF Surround。
  • 必须等实机/公开数据：Scout 实机十段、USB id↔频段、硬件回环、专有 HRTF/固件 DSP。
本报告基于静态逆向、独立对拍与已有抓包；不包含 Creative 原厂二进制或固件。 Sound Blaster、Sound BlasterX、G6 是 Creative Technology Ltd. 的商标。
