# 本地音频 / 输入输出设备 EQ 试听

日期：2026-11-12（UTC+8）。页面：audio-lab.html。原有 index.html 的预制样本 A/B 试听仍保留。

## 启动

双击 creative-sbcommand 根目录的 `start-eq-lab.cmd`。它使用项目已有 Python 环境，在127.0.0.1启动静态服务并打开浏览器。默认端口8767，若被其他应用占用则选择空闲端口，以控制台打印的地址为准。关闭服务请在控制台按Ctrl+C。

此增强页需要通过localhost/HTTPS打开，不能依赖直接双击HTML。服务只监听回环地址，不接受音频上传POST。浏览器选择的用户音频由File API和Web Audio在本地解码，不上传到服务器。

## 通用客户端 / 网页输出捕获

在“外部音频捕获”中点“刷新客户端进程”，按程序名或PID搜索并选择目标，点击“连接应用”，就绪后再点“开始监听”。支持目标及子进程树，不限制B站，后台候选也可选择。停止采集只停止辅助模块，不关闭目标程序。

网页音频可用“共享网页/系统音频”，选择需要的标签页并勾选共享音频；整屏混音不是单应用隔离。完整说明见[audio-capture-contract.md](audio-capture-contract.md)。

进程回环复制原声，不自动静音原客户端。只听EQ时，把原软件送到不直出的虚拟通道（例如VoiceMeeter），本页输出到耳机，避免原声/EQ叠音。未修改你的系统音频路由。

## 自选音频对比

1. 选择本地音频，或点击“加载合成诊断音”。至少支持浏览器能解码的WAV/MP3，其他格式取决于浏览器。
2. 选择34个预设之一，以及原厂数据的扬声器/耳机模式。
3. 点击播放，在“A原音 / B EQ”间切换；两者共用同一播放位置，切换使用短增益渐变。
4. 暂停后保留位置，支持拖动和循环。更换文件停止旧音源并取消过期解码回调。

默认额外增益-6 dB，另有共享主音量。A包含共享额外增益，B额外包含预设前级和10段EQ。没有自动压缩/限幅，若发生削波请降低增益或主音量。处理器为浏览器原生peaking BiquadFilter、Q=1；采样率以实际AudioContext为准，浏览器可能重采样。频响图包含预设前级与额外增益，不包含共享主音量。

## 输入输出设备

- “刷新设备”调用enumerateDevices，不请求麦克风；未授权时名称可能为空，只显示占位名。
- “授权设备名称”会明确请求一次麦克风权限，并立即停止临时轨道，以读取设备名称。
- “启用麦克风”按所选输入请求音频，关闭回声消除/降噪/自动增益；默认只捕获、不监听。
- 另点“开始监听”才会输出；监听时请使用耳机，避免扬声器回授。
- 停止麦克风、更换音源或离开页面会停止轨道、断开旧节点。等待权限时取消也会使迟到的stream失效并释放。
- 输出路由优先AudioContext.setSinkId，兼容路径为MediaStreamDestination和HTMLAudioElement.setSinkId；不可用或失败时明确显示系统默认/原路由，没有伪装切换成功。
- 浏览器是否提供selectAudioOutput、设备标签和指定输出权限，取决于浏览器与系统；建议使用Chrome或Edge。

## 预制试听音频

原始16秒诊断素材与33个不同曲线/基线文件见audio/README.md；68种模式均已映射。四个独立A→B示例中，前4秒为原音，0.25秒静音后是同一片段的EQ版。它们是合成诊断素材，不是真实游戏脚步、音乐或人声录音。

## 验证边界

真实Chrome自动化验收34/34通过，进程/传输验收14/14、流式缓冲与重采样验收12/12通过。新增检查包括自建静音进程的真实WASAPI回环到网页、合成标签页共享、无音频/权限拒绝/晚到结果的资源清理。原有回归包括：33份WAV读取、68个预制模式映射、原生WebAudio的68条EQ频响、本地文件解码、A/B位置保持、暂停与拖动、设备刷新不申请权限、授权名称后停止临时轨道、默认输出路由、虚拟麦克风默认不监听、B路监听、停止监听与释放轨道、页面资源清理和无音频POST上传。

网页原生EQ频响与图册最大差为0.0000027583 dB。测试采用隔离的临时浏览器配置、静音与虚拟麦克风，没有录取真人音频。默认输出已通过AudioContext.setSinkId真实API调用验证；指定你自己的物理设备、权限提示和实际听感仍需在浏览器授权后确认。完整结果及最终代码SHA256在audio/browser-validation.json；文件音频的波形、帧数、峰值和哈希在audio/audio-manifest.json。
